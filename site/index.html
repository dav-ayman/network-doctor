"My voice keeps breaking in meetings."

Speed tests say the line is fine. The real culprit is usually lag under load: when anything uploads or downloads, the router queues your voice packets behind it. network-doctor measures exactly that, on the same UDP path a call uses.

The numbers on the right come from the built-in demo network, the same synthetic data used in every recording on this page.

call probe · p95 latency · 10 packets/s
idle63 ms
uploading702 ms
downloading245 ms

While uploading, 61% of voice packets arrive later than 150 ms, which is too late to play. Bufferbloat grade: F.

How it works

One read-only checkup. You get ranked findings, each with evidence and a fix.

wifi

Wi-Fi

Signal, noise, channel and width, plus the neighbouring networks crowding it. It suggests the least busy channel.

bloat

Lag under load

Measures latency while idle, while uploading and while downloading, and grades bufferbloat from A+ to F.

call

Call quality

Loss, jitter and late packets from a voice-like UDP stream to the STUN servers Meet and others use.

mtu · dns

Black holes

Finds PPPoE/VPN MTU problems that make some sites hang, and slow or failing DNS.

router

Your router

4G/5G RSRP, RSRQ, SINR and band; Wi-Fi config; clients; QoS. Read straight from the router's own API.

fix

Fix, then prove it

It shows a plan, applies it after you approve, saves a backup, then re-measures so you see the before and after.

Talks to your router

It reads the cellular signal, Wi-Fi and clients. Every change starts as a plan showing the current and new values. Nothing is sent until you approve it.

Detect

Identifies the router with read-only requests. No login.

Read

Logs in with the password from your OS keychain, and logs out after.

Plan, approve, apply

Automatic backup, plus a one-line revert.

Install

Nothing to pip install: it needs only Python 3.9+, which ships with macOS developer tools and every Linux. It runs on your computer, so it measures your real network.

/plugin marketplace add dav-ayman/network-doctor
/plugin install network-doctor@network-doctor

Then describe the problem in plain words: "my calls keep breaking up", "why is my Wi-Fi slow?", "check my 5G router's signal". You get the skill and 16 MCP tools.

  1. Download network-doctor-<version>.mcpb from the latest release.
  2. Double-click it, or open Claude Desktop, go to Settings > Extensions and drag it in.
  3. Click Install, then ask: "my voice keeps breaking up in meetings, what's wrong?"

When Claude needs your router password, it opens a Terminal window where you type it into your OS keychain. The password never goes into the chat.

git clone https://github.com/dav-ayman/network-doctor
cd network-doctor
python3 plugins/network-doctor/skills/network-doctor/scripts/netdoc.py diagnose --demo

--demo runs on a synthetic network. Drop it to measure yours. netdoc.py --help lists every command.

Built to be safe with your router

Routers lock the admin account after a few wrong passwords, and a bad setting can cut you off. So the rules are strict.

keychain

Passwords never touch the chat

They live in the macOS Keychain or Linux Secret Service, and every output is masked.

bound

Tied to your router

Each stored password is bound to the router's hardware address, so your home password is never offered to the café's 192.168.1.1.

no-retry

No lockouts

A rejected password is remembered, and netdoc won't try again until you fix it. That's one attempt per run, ever.

plan

Plan before change

Every write shows the current and new values first. It runs only after you approve, with a backup and an undo.

FAQ

Does it work with Claude on the web?

Not for measuring your network. Claude on the web runs code in a cloud sandbox, which can't see your Wi-Fi or router. Use Claude Code or the Claude Desktop extension: both run locally.

Will the test slow my connection?

For about 45 seconds the full checkup saturates your upload, then your download. That's how it measures lag under load. Use the quick mode, or skip the load test, if someone is on a call.

Which operating systems?

macOS is first class, and Linux is supported (Wi-Fi details via iw/nmcli). Windows isn't supported yet.

Does it send my data anywhere?

No telemetry. Measurements reach public STUN servers, Cloudflare's speed endpoints (or Apple's networkQuality on macOS) and 1.1.1.1. Router traffic goes only to your router.

My router isn't supported. Can you add it?

Very likely. Run netdoc.py capture and open an "Add my router" issue. The masked capture is enough for someone to write a driver without owning the hardware.
